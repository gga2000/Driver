# J3a — Istikan look (foundation + home) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the customer app the Istikan look (joy spec J-D1/J-D2, §5.3 J3, report 5 §5 Direction A) — new tokens, two brand faces, role-driven components, service glyphs and the new home — while the Partner and Merchant apps and the Console stay pixel-identical.

**Architecture:** A third theme `istikan` joins `light`/`dark` in `@driver/design-tokens`. Every new semantic role exists in all three themes; in `light`/`dark` each new role takes the exact value the component drew before (so shared components look the same in the other apps), and only `istikan` carries the new colour logic (tea = act and eat, kashi = move and live, ink = choose, saffron = treat). Shared components in `@driver/ui` read roles, never theme names; the customer root `ThemeProvider` switches to `istikan`. Brand faces (Alexandria, Marhey) are opt-in through a `face` prop on `Text`, so nothing changes where it isn't asked for.

**Tech Stack:** TypeScript, React Native 0.76 + react-native-web (Expo SDK 52), Vitest, `@expo-google-fonts/alexandria`, `@expo-google-fonts/marhey`, react-native-svg.

**Constraints:** Another session (driver-a6) edits customer/partner/merchant builders and may add a `columns` prop to `ChipGroup`; it touches `LatePromise.tsx` and the الرجعة `DepartureTime` note tone. This plan only changes `Chip`/`ChipGroup` colours (no props or layout) and never edits `LatePromise.tsx` or `DepartureTime`.
